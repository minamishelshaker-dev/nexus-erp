# RBAC Permission Gaps – 2026-11-19

The endpoint permission strings were compared with the canonical permission constants in `app/core/rbac.py`.

## Safe name aliases added
These are naming-only translations to existing canonical permissions:
- `accounting.account.*` → `accounting.accounts.*`
- `crm.customer.*` → `crm.customers.*`
- `sales.quotation.read` → `sales.quotations.view`
- `sales.order.*` → `sales.orders.*`
- `sales.invoice.*` → `sales.invoices.*`
- `purchase.order.*` → `purchase.orders.*`
- `purchase.receipt.read` → `purchase.receipt.view`
- `inventory.stock.create` → `inventory.movements.create`
- `manufacturing.order.*` → `manufacturing.orders.*`
- manufacturing BOM/workcenter read aliases to their existing `view` permissions.

## Missing permissions – must be designed and seeded explicitly
The following endpoint permissions do not have a safe equivalent in the current permission catalogue. They remain fail-closed and should not be mapped to a broader permission merely to make an endpoint work:
- `ai.chat.create`, `ai.chat.read`
- `ai.forecast.create`, `ai.forecast.read`
- `ai.ocr.create`, `ai.ocr.read`
- `accounting.journal.reverse`
- `inventory.stock.confirm`, `inventory.stock.process`, `inventory.stock.cancel`, `inventory.stock.delete`
- `manufacturing.workcenter.create`
- `purchase.invoice.create`, `purchase.invoice.read`, `purchase.invoice.update`
- `purchase.receipt.update`
- `sales.payment.create`

## Required next action
Define the complete permission registry (including module/resource/action and scope), add migration/seed logic for permission rows and role assignments, and test every protected endpoint as allowed and denied for representative roles. Do not use permissive wildcards to conceal missing definitions.
