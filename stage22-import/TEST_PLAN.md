## 2. سيناريوهات التشغيل الأساسية (Smoke Tests)

### 2.1 تسجيل مستخدم جديد وتسجيل الدخول

**الهدف:** التحقق من عمل نظام المصادقة بشكل كامل

**الخطوات:**
1. فتح صفحة التسجيل `/register`
2. إدخال البيانات المطلوبة:
   - اسم المستخدم: `testuser001`
   - البريد الإلكتروني: `testuser001@example.com`
   - كلمة المرور: `Test@123456`
   - تأكيد كلمة المرور: `Test@123456`
3. الضغط على زر "تسجيل"
4. التحقق من ظهور رسالة النجاح
5. الانتقال إلى صفحة تسجيل الدخول `/login`
6. إدخال بيانات الاعتماد
7. الضغط على "دخول"

**النتائج المتوقعة:**
- [ ] إنشاء الحساب بنجاح
- [ ] إرسال بريد تأكيد (إن كان مفعلاً)
- [ ] تسجيل الدخول بنجاح
- [ ] الحصول على رمز JWT صالح
- [ ] توجيه المستخدم للوحة التحكم

**بيانات الاختبار:**
```json
{
  "username": "testuser001",
  "email": "testuser001@example.com",
  "password": "Test@123456"
}
```

---

### 2.2 إنشاء منتج جديد

**الهدف:** التحقق من عمل وحدة المخزون

**الخطوات:**
1. تسجيل الدخول كمستخدم له صلاحية `inventory.product.create`
2. الانتقال إلى المخزون > المنتجات
3. الضغط على "إضافة منتج جديد"
4. إدخال البيانات:
   - اسم المنتج: "لابتوب HP ProBook"
   - الرمز/SKU: "LAP-HP-001"
   - الفئة: "أجهزة الكتبيوتر"
   - سعر التكلفة: 2500.00
   - سعر البيع: 3000.00
   - الوحدة: قطعة
   - قابل للتخزين: نعم
5. حفظ المنتج

**النتائج المتوقعة:**
- [ ] إنشاء المنتج برمز فريد
- [ ] ربط المنتج بالحسابات المحاسبية الافتراضية
- [ ] ظهور المنتج في قائمة المنتجات
- [ ] الكمية الحالية = 0

**API Endpoint:**
```
POST /api/v1/inventory/products
```

---

### 2.3 استلام مخزون (عملية شراء)

**الهدف:** التحقق من تدفق الشراء → المخزون → المحاسبة

**الخطوات:**
1. إنشاء أمر شراء من مورد
2. إضافة بنود:
   - منتج: LAP-HP-001
   - الكمية: 10
   - السعر: 2500.00
3. تأكيد أمر الشراء
4. استلام البضاعة
5. التحقق من:
   - تحديث كمية المخزون
   - إنشاء قيد محاسبي تلقائي

**النتائج المتوقعة:**
- [ ] تحويل أمر الشراء من "مسودة" إلى "مؤكد"
- [ ] زيادة كمية المخزون بـ 10 وحدات
- [ ] إنشاء قيد محاسبي:
  - مدين: المخزون 25,000
  - دائن: المورد/GR-IR 25,000

---

### 2.4 بيع منتج (فاتورة مبيعات)

**الهدف:** التحقق من تدفق البيع → المخزون → المحاسبة

**الخطوات:**
1. إنشاء عرض سعر للعميل
2. تحويل العرض لأمر بيع
3. تأكيد أمر البيع
4. إنشاء الفاتورة
5. ترحيل الفاتورة

**النتائج المتوقعة:**
- [ ] نقص المخزون بالكمية المباعة
- [ ] إنشاء قيد محاسبي:
  - مدين: العميل 30,000
  - دائن: المبيعات 30,000
- [ ] إنشاء قيد تكلفة البضاعة المباعة:
  - مدين: تكلفة البضاعة المباعة 25,000
  - دائن: المخزون 25,000

---

### 2.5 إنشاء قيد محاسبي يدوي

**الهدف:** التحقق من عمل نظام القيود المحاسبية

**الخطوات:**
1. الانتقال إلى المحاسبة > القيود اليومية
2. الضغط على "قيد جديد"
3. إدخال التاريخ والوصف
4. إضافة البنود:
   - الصندوق (مدين) 5,000
   - المبيعات (دائن) 5,000
5. حفظ وترحيل القيد

**النتائج المتوقعة:**
- [ ] التحقق من توازن القيد (المدين = الدائن)
- [ ] إنشاء القيد برقم تسلسلي
- [ ] تحديث أرصدة الحسابات
- [ ] ظهور القيد في ميزان المراجعة

---

### 2.6 تشغيل تقرير مالي

**الهدف:** التحقق من صحة التقارير المالية

**التقارير المطلوب اختبارها:**

#### أ. ميزان المراجعة (Trial Balance)
```
GET /api/v1/reports/trial-balance?date=2024-12-31
```
- [ ] مجموع المدين = مجموع الدائن
- [ ] جميع الحسابات ظاهرة بأرصدتها

#### ب. قائمة الدخل (Income Statement)
```
GET /api/v1/reports/income-statement?from=2024-01-01&to=2024-12-31
```
- [ ] الإيرادات - المصروفات = صافي الربح
- [ ] تطابق الأرقام مع القيود

#### ج. الميزانية العمومية (Balance Sheet)
```
GET /api/v1/reports/balance-sheet?date=2024-12-31
```
- [ ] الأصول = الخصوم + حقوق الملكية

### 2.7 إنشاء أمر تصنيع

**الهدف:** التحقق من عمل وحدة التصنيع

**الخطوات:**
1. إنشاء قائمة مواد (BOM) لمنتج نهائي
2. إنشاء أمر تصنيع جديد:
   - المنتج: منتج نهائي
   - الكمية: 5
   - BOM: قائمة المواد المعدة
3. تأكيد الأمر
4. بدء الإنتاج
5. استهلاك المواد
6. إنهاء الإنتاج

**النتائج المتوقعة:**
- [ ] نقص المواد الخام من المخزون
- [ ] زيادة المنتج النهائي في المخزون
- [ ] إنشاء قيود محاسبية للتصنيع

### 2.8 استخدام المساعد الذكي (Chatbot)

## 3. سيناريوهات التكامل (Integration Tests)

### 3.1 دورة البيع الكاملة

**الوصف:** اختبار التدفق الكامل من عرض السعر حتى القيد المحاسبي

```
عرض سعر → أمر بيع → تسليم → فاتورة → قيد محاسبي
```

**الخطوات التفصيلية:**

| # | العملية | الحالة المتوقعة | التحقق |
|---|---------|-----------------|--------|
| 1 | إنشاء عرض سعر | draft | رقم العرض |
| 2 | إضافة بند (منتج، كمية، سعر) | - | المجموع الفرعي |
| 3 | تأكيد العرض | sent | رقم أمر البيع |
| 4 | تحويل لأمر بيع | confirmed | - |
| 5 | تأكيد أمر البيع | confirmed | حجز المخزون |
| 6 | إنشاء تسليم | done | نقص المخزون |
| 7 | إنشاء فاتورة | posted | رقم الفاتورة |
| 8 | التحقق من القيود | posted | 2 قيود |

**القيود المحاسبية المتوقعة:**

**القيد الأول (الإيراد):**
| الحساب | مدين | دائن |
|--------|------|------|
| العملاء | XXX | - |
| المبيعات | - | XXX |
| ضريبة المبيعات | - | XX |

**القيد الثاني (التكلفة):**
| الحساب | مدين | دائن |
|--------|------|------|
| تكلفة البضاعة المباعة | XX | - |
| المخزون | - | XX |

---

### 3.2 دورة الشراء الكاملة

**الوصف:** اختبار التدفق الكامل من طلب الشراء حتى القيد المحاسبي

```
طلب شراء → أمر شراء → استلام → فاتورة مورد → قيد محاسبي
```

**الخطوات التفصيلية:**

| # | العملية | الحالة المتوقعة | التحقق |
|---|---------|-----------------|--------|
| 1 | إنشاء طلب شراء | draft | رقم الطلب |
| 2 | الموافقة على الطلب | approved | - |
| 3 | إنشاء أمر شراء | sent | رقم الأمر |
| 4 | تأكيد أمر الشراء | confirmed | - |
| 5 | استلام البضاعة | done | زيادة المخزون |
| 6 | إنشاء فاتورة مورد | posted | رقم الفاتورة |
| 7 | التحقق من القيود | posted | 2 قيود |

---

### 3.3 دورة التصنيع الكاملة

**الوصف:** اختبار التدفق الكامل من BOM حتى المنتج النهائي

```
BOM → أمر تصنيع → استهلاك مواد → إنتاج → قيود محاسبية
```

**السيناريو:**
- المنتج النهائي: طاولة خشبية
- المواد الخام: خشب (10 وحدات)، مسامير (50 وحدة)
- قوة العمل: 2 ساعات

**القيود المحاسبية المتوقعة:**

**استهلاك المواد:**
| الحساب | مدين | دائن |
|--------|------|------|
| قيد التشغيل | 500 | - |
| مخزون الخشب | - | 300 |
| مخزون المسامير | - | 200 |

**الإنتاج:**
| الحساب | مدين | دائن |
|--------|------|------|
| مخزون المنتج النهائي | 700 | - |
| قيد التشغيل | - | 500 |
| مصاريف قوة العمل | - | 200 |

---

### 3.4 رفع فاتورة OCR وإنشاء فاتورة تلقائياً

**الوصف:** اختبار قدرة النظام على قراءة الفواتير بالذكاء الاصطناعي

**الخطوات:**
1. رفع صورة فاتورة بصيغة PDF/PNG
2. انتظار معالجة OCR
3. مراجعة البيانات المستخرجة
4. إنشاء فاتورة مورد من البيانات

**النتائج المتوقعة:**
- [ ] استخراج رقم الفاتورة
- [ ] استخراج التاريخ
- [ ] استخراج اسم المورد
- [ ] استخراج البنود والكميات والأسعار
- [ ] استخراج المجموع الكلي
- [ ] دقة الاستخراج > 90%

## 4. سيناريوهات الحالات الشاذة (Edge Cases)

### 4.1 قيد محاسبي غير متوازن

**السيناريو:** محاولة إنشاء قيد حيث المدين ≠ الدائن

**الخطوات:**
1. إنشاء قيد جديد
2. إضافة بنود:
   - الصندوق (مدين) 1000
   - المبيعات (دائن) 800
3. محاولة الحفظ

**النتيجة المتوقعة:**
- [ ] رفض القيد مع رسالة خطأ واضحة
- [ ] "القيد غير متوازن. الفرق: 200"
- [ ] HTTP 422 Unprocessable Entity

---

### 4.2 بيع منتج غير متوفر في المخزون

**السيناريو:** محاولة بيع كمية أكبر من المتاح

**الخطوات:**
1. منتج A - الكمية المتاحة: 5
2. إنشاء أمر بيع بكمية 10
3. محاولة التأكيد

**النتيجة المتوقعة:**
- [ ] تحذير من نقص المخزون
- [ ] خيارات:
  - إلغاء الأمر
  - تعديل الكمية
  - إنشاء أمر شراء تلقائي
- [ ] عدم نقص المخزون دون التأكيد

---

### 4.3 إلغاء أمر بعد تنفيذه جزئياً

**السيناريو:** إلغاء أمر شراء تم استلام جزء منه

**الخطوات:**
1. أمر شراء بكمية 100
2. استلام 40 وحدة
3. محاولة إلغاء الأمر

**النتيجة المتوقعة:**
- [ ] تحذير من وجود استلامات مرتبطة
- [ ] خيارات:
  - إلغاء الكمية المتبقية فقط
  - إرجاع المستلم وإلغاء كامل
- [ ] إنشاء قيود عكسية عند الإرجاع

---

### 4.4 تاريخ قيد في فترة مغلقة

**السيناريو:** محاولة إنشاء قيد بتاريخ فترة محاسبية مغلقة

**الخطوات:**
1. إغلاق الفترة المحاسبية لشهر يناير
2. محاولة إنشاء قيد بتاريخ 15 يناير

**النتيجة المتوقعة:**
- [ ] رفض القيد
- [ ] رسالة: "الفترة المحاسبية مغلقة"
- [ ] اقتراح الفترة المفتوحة التالية

---

### 4.5 حذف منتج له حركات مخزون

**السيناريو:** محاولة حذف منتج له سجل حركات

**الخطوات:**
1. منتج له مشتريات ومبيعات
2. محاولة الحذف

**النتيجة المتوقعة:**
- [ ] رفض الحذف
- [ ] رسالة: "لا يمكن حذف المنتج لوجود حركات مرتبطة"
- [ ] خيار: أرشفة المنتج بدلاً من الحذف

---

### 4.6 تسجيل دخول بخطأ متكرر

**السيناريو:** محاولات تسجيل دخول فاشلة متعددة

**الخطوات:**
1. إدخال كلمة مرور خاطئة 5 مرات متتالية

**النتيجة المتوقعة:**
- [ ] قفل الحساب مؤقتاً (15 دقيقة)
- [ ] رسالة واضحة للمستخدم
- [ ] تسجيل محاولات الدخول الفاشلة

## 6. اختبارات الأمان (Security Tests)

### 6.1 المصادقة والتفويض

| الاختبار | الوصف | النتيجة المتوقعة |
|----------|-------|------------------|
| JWT منتهي | استخدام token منتهي | 401 Unauthorized |
| JWT بدون صلاحية | الوصول لـ endpoint محمي | 403 Forbidden |
| SQL Injection | إدخال code في الحقول | رفض / sanitize |
| XSS | إدخال script | رفض / escape |

### 6.2 عزل البيانات (Multi-tenancy)

- [ ] مستخدم من شركة A لا يرى بيانات شركة B
- [ ] tenant_id يُطبق على جميع الاستعلامات
